# Permits and Approvals Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Collect every special use permit, variance and site plan the City of Alexandria publishes, keep them in a committed catalog, attach them to lots, and let a matching permit settle a rule as "permit on file", with links to the city's documents in the pop-up.

**Architecture:** A new `alx_zoning_illegal_homes/permits/` package collects cases from two city map layers and the city's document archive. It merges them into a committed, add-only catalog (`catalog.jsonl`) and downloads documents into the git-ignored `data/permits/`. During `create-map`, `analyze.py` matches cases to lots, tags what each case grants, and lifts matching rule rows to a new `permit_on_file` status. The lot files carry a `permits` list that the pop-up shows.

**Tech Stack:** Python 3.11, uv, geopandas/shapely, requests (already a dependency), the standard library's `html.parser` for archive pages, pytest; plain ES modules and `node --test` for the pop-up.

**Spec:** `docs/superpowers/specs/2026-11-24-permits-design.md`

## Global Constraints

- Use pnpm for Node, uv for Python, and add no new dependencies. Use `requests` and the standard library only.
- Network hosts: `imaging.alexandriava.gov`, `geoportal.alexandriava.gov`, `maps.alexandriava.gov`. In this sandbox, network commands run with the sandbox off, and `uv` needs `UV_CACHE_DIR="$TMPDIR/uv-cache"`.
- Wait at least 1 second between archive requests. The user agent is `alx-zoning-illegal-homes permit collector`, with no personal details.
- Tests never touch the network. They read saved pages from `tests/fixtures/permits/`.
- The catalog `alx_zoning_illegal_homes/permits/catalog.jsonl` is committed, sorted by case number, one JSON object per line. Merging only adds or fills in. It never blanks a field or drops a case.
- Downloaded PDFs go to `data/permits/pdf/<case>/<document id>.pdf`, which is git-ignored because all of `data/` is. Builds never delete them.
- The site links only to the city's originals. Nothing is copied into `site/`.
- A missing permit never changes a rule's result.
- Plain wording in every user-facing string. Docstrings over inline comments.

## Review Focus

1. The same case written differently by different sources (`SUP2005-00035`, `SUP 2005-0035`, `SUP#2005-35`, `sup2005-00035`) must end up as one catalog line. Tested in Task 2.
2. A crawl that stops halfway (server error, expired cookie session, Ctrl-C) must resume without duplicates or lost fields. Tested in Tasks 2 and 4.
3. The archive often gives parcel ID `0` or blank. That must never match a parcel. Matching falls back to the address instead. Tested in Task 5.
4. A business permit on a mixed-use lot ("restaurant", "parking reduction") must not lift any home rule. It's listed only. Tested in Task 6.
5. Addresses with unit numbers ("2121 JAMIESON AVE UNIT 809") or old street names ("JEFFERSON DAVIS HY" for today's Richmond Highway) still match. Tested in Task 5.

  - `KEYWORDS: list[tuple[str, re.Pattern]]`: the tag and its pattern, written as one readable table at the top of the module. Variance tags apply only to `BZA` cases and come from the yard or rule named in the description:

    - `side yard` gives `variance:yard:left` and `variance:yard:right`

    - `height` gives `variance:height`
    - `floor area|FAR` gives `variance:floor_area`
    - `open space` gives `variance:open_space`
    - `frontage` gives `variance:frontage`
    - `lot width` gives `variance:width`
    - `lot (area|size)` gives `variance:lot_area`
  - `tags_for(case: dict) -> set[str]`: matches the case's `descriptions` and its documents' `type`s

An override can set `"tags"` (replacing the keyword tags), `"parcel_ids"` (added), `"ignore": true` (drops the case from matching but not from the catalog file), and needs a `"source"` note.
